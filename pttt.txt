Excelente descubrimiento — estas dos queries de Bryan son literalmente el origen de `BD_Stock_Cartera` y `BD_Desembolsos` en Power BI. La primera resuelve exactamente el problema que identificamos: **cómo separar Fuga de Amortización a nivel de crédito individual**. Te explico la lógica y después te dejo tu query diaria adaptada.

### Qué hace realmente la Query 1 de Bryan

Trabaja a **nivel de crédito** (CIF_KEY + NRO_CREDITO), no a nivel de portafolio agregado como tu query diaria. Por cada crédito, compara el saldo del mes anterior contra el mes actual y lo clasifica:

| CondiciónClasificación                                              |                                                    |
| ------------------------------------------------------------------- | -------------------------------------------------- |
| El crédito desembolsó este mes                                      | **NUEVOS** (sin importar si ya tenía saldo previo) |
| No desembolsó, tenía saldo el mes anterior, y ahora tiene saldo = 0 | **FUGA** = -saldo_anterior                         |
| No cae en los anteriores y sigue con saldo ≠ 0                      | **AMORTIZACION** = saldo_actual - saldo_anterior   |
| Nada de lo anterior                                                 | OTROS (no aporta)                                  |

El detalle más importante — y el que se te va a escapar fácilmente si adaptas esto rápido — es este bloque:

sql
```sql
WHEN TIPO_MOVIMIENTO = 'NUEVOS'
    THEN SALDO_ACTUAL - MONTO_DESEMBOLSADO
```

Si un crédito **ya existía y además desembolsó** en el mismo periodo, Bryan no lo separa: lo clasifica 100% como NUEVOS, pero luego "rescata" cualquier movimiento adicional (pagos parciales sobre ese mismo crédito) metiéndolo dentro de `AMORTIZACION` mediante esta resta. Si omites esto al adaptar tu query, vas a **subestimar la amortización** en los créditos que desembolsan y pagan en el mismo intervalo.

### Advertencia antes de adaptar

Bryan usa `FDM.FEM_ALL_INSTR` + `DOCUM_APL_ID` como identificador de crédito. Tu query diaria usa `FDM.FEM_SALDOS_DIARIOS` + `ACCOUNT_NUMBER`. **Necesitas confirmar que `ACCOUNT_NUMBER` en `FEM_SALDOS_DIARIOS` es el mismo identificador de crédito que `DOCUM_APL_ID` en `FEM_ALL_INSTR`** (mismo grano, mismos valores) antes de confiar en la adaptación — si son tablas con grano distinto, la clasificación por crédito no va a cuadrar. Esto no lo puedo verificar yo sin acceso a tu Oracle.

### Tu query diaria adaptada

La idea central: en vez de trabajar solo con el stock total agregado (como en tu query actual), primero bajas a nivel de crédito, aplicas la clasificación de Bryan por cada intervalo entre snapshots (no por mes), y **después** agregas. Esto convierte `ERROR_RECONCILIACION` en una validación real — ya no será tautológicamente cero.

&#x20;   FROM SECUENCIA S
\
&#x20;   JOIN STOCK_DIARIO SD_ACT ON SD_ACT.FECHA = S.FECHA_SNAPSHOT
\
&#x20;   LEFT JOIN STOCK_DIARIO SD_ANT ON SD_ANT.FECHA = S.FECHA_SNAPSHOT_ANT
\
&#x20;   LEFT JOIN MOVIMIENTOS_INTERVALO MM ON MM.FECHA_SNAPSHOT = S.FECHA_SNAPSHOT
\
&#x20;   WHERE S.FECHA_SNAPSHOT_ANT IS NOT NULL
\
)
\

\
/\* ============================================================
\
&#x20;  RESULTADO FINAL — ahora ERROR_RECONCILIACION es una prueba
\
&#x20;  REAL: Nuevos, Amortizacion y Fuga se calcularon de forma
\
&#x20;  independiente al Stock, a nivel de credito. Si no cierra,
\
&#x20;  hay un problema real que investigar (no un plug algebraico).
\
&#x20;  \============================================================ \*/
\
SELECT
\
&#x20;   FECHA_SNAPSHOT,
\
&#x20;   FECHA_SNAPSHOT_ANT,
\
&#x20;   FECHA_SNAPSHOT - FECHA_SNAPSHOT_ANT AS DIAS_INTERVALO,
\

\
&#x20;   ROUND(STOCK_INICIAL, 2)   AS STOCK_INICIAL,
\
&#x20;   ROUND(STOCK_FINAL, 2)     AS STOCK_FINAL,
\

\
&#x20;   ROUND(NVL(NUEVOS,0), 2)       AS NUEVOS,
\
&#x20;   ROUND(NVL(AMORTIZACION,0), 2) AS AMORTIZACION,
\
&#x20;   ROUND(NVL(FUGA,0), 2)         AS FUGA,
\

\
&#x20;   CLIENTES_INICIAL,
\
&#x20;   CLIENTES_FINAL,
\
&#x20;   CREDITOS_INICIAL,
\
&#x20;   CREDITOS_FINAL,
\

\
&#x20;   /\* Reconciliacion REAL (ya no tautologica) \*/
\
&#x20;   ROUND(
\
&#x20;       STOCK_INICIAL + NVL(NUEVOS,0) + NVL(AMORTIZACION,0) + NVL(FUGA,0),
\
&#x20;       2
\
&#x20;   ) AS STOCK_CALCULADO,
\

\
&#x20;   ROUND(
\
&#x20;       STOCK_FINAL - (STOCK_INICIAL + NVL(NUEVOS,0) + NVL(AMORTIZACION,0) + NVL(FUGA,0)),
\
&#x20;       2
\
&#x20;   ) AS ERROR_RECONCILIACION
\

\
FROM SNAPSHOTS
\
ORDER BY FECHA_SNAPSHOT;
